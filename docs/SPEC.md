# GOAT Tweaks — build spec (authoritative; sidekick implements against this)

License: AGPL-3.0 (RyTuneX code reused). Keep upstream LICENSE files + NOTICE listing all four + their commit SHAs.

## Golden rule
Every action runs the ORIGINAL upstream command/script/method BYTE-FOR-BYTE. We never retype or paraphrase a command. We embed upstream source as data/resources and execute it. SHA-256 of each embedded upstream file is checked at build and (where embedded as files) at runtime; mismatch => action disabled with a visible reason. No silent behavior change.

## Repo layout (~/repos/goat-tweaks)
- `catalog/catalog.json` — generated by `tools/gen_catalog.py` (DO NOT hand-edit). 602 items.
- `src/GoatTweaks/` — WPF app (net10.0-windows, EnableWindowsTargeting=true, win-x64, self-contained single-file).
- `src/GoatTweaks.Runner/` — tiny console exe invoked elevated for batched admin actions + `--rytunex` mode.
- `third_party/` — verbatim copies of upstream files we embed (Ultimate scripts, WinSux scripts, winutil functions+configs, RyTuneX cs). Copied by `tools/sync_third_party.sh` with SHA manifest.
- `tests/` — xUnit (catalog integrity, SHA verbatim checks, command-builder validation) + Pester (ps harness) run on Windows only.

## App shell (single window, nav)
- Title bar text is exactly `GOAT Tweaks`. No subtitle/slogan/other brand anywhere.
- Left NavigationView, one item per source-grouped section: Optimize, Privacy, Features, Debloat (AppX), Install Apps, Network/DNS, Repair, Security, Power, Advanced, WinSux (full pipeline), Logs. Each action card shows: title, description, source badge (RyTuneX/WinSux/Ultimate/winutil), risk badge, admin badge, revert availability.
- Search box filters cards across all sections.
- Every action card -> "Preview" opens a dialog showing the EXACT command text / script path+SHA / method name that will run, admin requirement, revert availability, and irreversibility warning. Sensitive (risk=high or irreversible) require typed confirmation.
- Selected actions queue; one "Apply selected" batches all admin actions into ONE elevated Runner invocation (one UAC prompt). Non-admin actions run in-process.

## Failure isolation + logging
Each action = its own child process (or isolated try/catch task). One failure never aborts others. Per-action log row (timestamp, id, source, command, exit code, stdout/stderr tail) appended to `%LOCALAPPDATA%\GoatTweaks\logs\run-<timestamp>.jsonl` and shown in Logs page.

## Engines (all preserve upstream exactly)
1. **ultimate** — run original `.ps1` unmodified via `powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<path>"` (Windows PowerShell 5.1, matching upstream). Interactive menu scripts: UI presents the parsed options (catalog `options`) + validated fields for `freeInputs`; selected answers are fed on the child's STDIN as lines (verified: Read-Host + nested Read-Host read redirected stdin). Runner must send the chosen menu key, then any free-input lines in prompt order, then close stdin; watchdog timeout kills a spinning menu. Scripts self-elevate already; when we run them inside the elevated Runner they won't re-prompt. Launcher-only scripts (no admin header, just open settings/URLs) run in-process non-elevated.
   - freeInputs needing validation (from catalog): Priority (8/10) game exe id + priority choice; Smt Ht / Core 1 Thread 1 exe id; Autounattend account name + USB drive letter; Updates Drivers Block USB letter. Validate against explicit regex BEFORE building stdin (letter: ^[A-Za-z]$; exe id/name: non-empty, no CR/LF). Never interpolate user text into a command string — it only ever goes to stdin as the script's own Read-Host answer.
2. **winutil** — harness `third_party/winutil/harness.ps1` (sidekick writes it; it may only dot-source + call original functions, no reimplementation) dot-sources the needed original `functions/*.ps1` and builds `$sync.configs` from original `config/*.json` exactly like `Compile.ps1` does (`Get-Content -Raw | ConvertFrom-Json`), then calls the original private/public functions: `Invoke-WinUtilTweaks -CheckBox <key>` (apply) / `-undo` (revert); `Invoke-WinUtilFeatureInstall <key>`; `Remove-WinUtilAPPX -Name <PackageId>`; `Set-WinUtilDNS -DNSProvider <key>`; app install via original `Install-WinUtilProgramWinget -Action Install -Programs <winget id>`. Provide stub `$sync` hashtable with keys: configs, logPath, transcriptPath, winutildir, LoggedErrors=@{}, IsLocalCompile=$true, ToggleStatusCache=@{}. No winutil UI is loaded.
3. **rytunex** — compile original `Helpers/OptimizeSystemHelper.cs`, `Helpers/OptimizationOptions.cs` (StartInCmd/RunPowerShell + ExecuteToggleActionAsync), `Helpers/LogHelper.cs`, `Helpers/MemoryHelper` and their minimal deps into GoatTweaks.Runner, VERBATIM (no edits; if a dep is missing, add the original file, don't stub). Toggle => `GoatTweaks.Runner --rytunex <tag> on|off` which calls `OptimizationOptions.ExecuteToggleActionAsync(tag, isOn)`. WindowsUpdates combo => the four `SetWindowsUpdates*` methods by option. Persisted state stays under RyTuneX's own `HKLM\SOFTWARE\RyTuneX\Optimizations` (unchanged). Excluded (no upstream UI): OneDrive, LocationAccess — list them in NOTICE as intentionally not exposed.
4. **winsux** — one action "WinSux (full pipeline)": runs original `winsux.ps1` unchanged. Irreversible; needs typed confirmation + explicit "reboots into Safe Mode, disables Defender/UAC/VBS, removes most UWP apps, no automatic revert" warning. We embed the repo's own copies of stepone/steptwo/reg.reg/settimerresolutionservice.cs so the pipeline is auditable, but winsux.ps1 itself downloads them at runtime (document this).

## Conflicts (see CONFLICTS.md, keep updated)
Same setting set by multiple sources (UAC EnableLUA, power plan, timer resolution, telemetry, Game Bar, Defender, etc.). Policy: never auto-run two conflicting actions silently. When queued selection contains 2+ actions touching the same documented key with different values, block Apply and show a resolution dialog; record the chosen one + dropped ones in the log. Duplicate (100%-identical) actions across WinSux/Ultimate are shown once with both source badges.

## Build/verify (sidekick runs on Linux)
- `dotnet publish src/GoatTweaks -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -p:EnableWindowsTargeting=true`
- `dotnet test` (xUnit, runs on Linux: catalog integrity, SHA manifest match, command-builder/regex validation, conflict-detector unit tests). Pester/live tests are Windows-only -> deferred to VM.
- Report back AT THE PUSH. Do not run the Windows VM tests (lead does that).
