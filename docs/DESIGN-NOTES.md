## Findings
- Ultimate: each script self-elevates (header), menu "N. X: On/Default" + `while($true){Read-Host; switch}`; branches end with `exit`. Files have no BOM (ASCII). Some scripts: nested Read-Host (Priority, Smt Ht, Core1Thread1: game exe id; Autounattend: account name + USB letter; Updates Drivers Block: USB letter). Several only open ms-settings/URLs (no admin header). Run-Trusted (TrustedInstaller binPath hijack) used in Gamebar, Control Panel Settings, Defender Optimize, Autoruns, Defender, Services.
- WinSux: winsux.ps1 (needs internet, downloads stepone/steptwo/reg.reg/... from raw *main* + binaries from releases/Files: 7zip, vcredist x12, ddu, helium, directx) -> installs, removes most UWP, RunOnce stepone (safe mode) + steptwo, bcdedit safeboot minimal, reboot. stepone: Defender/SmartScreen/VBS/LSA/driver blocklist off via Run-Trusted+admin, UAC off, remove safeboot, DDU, reboot. steptwo: remove Edge, UWP apps/features, legacy features/apps, store settings, windows settings (reg.reg + much), power plan, timer resolution (compiles csc service), cleanup, restore point, reboot.
- WinSux steptwo sections largely duplicate Ultimate scripts (e.g. POWER PLAN == Ultimate 6 Windows/29 option 1) -> dedupe after normalized diff.
- winutil: headless mode `winutil.ps1 -Config x.json` / `-Preset` (Invoke-WinUtilAutoRun) for tweaks/toggles/features/apps/appx; no headless undo. Core fn Invoke-WinUtilTweaks(-CheckBox, -undo) only needs $sync.configs (+ToggleStatusCache, logging). Registry entries have OriginalValue, services OriginalType -> undo.
- RyTuneX: toggles by Tag -> OptimizationOptions.ExecuteToggleActionAsync(tag,isOn) switch (119 cases) -> OptimizeSystemHelper.* which only depends on OptimizationOptions.StartInCmd (cmd.exe /C, hidden) + LogHelper. ~118 toggles across OptimizeSystem(44)/Features(40)/Privacy(34). Also non-toggle tools: Network (DNS apply/flush/release-renew/reset TCPIP), Repair, Security (quick scan, sig update, links), Services/Startup/Processes managers, Debloat (uninstall apps), Packages (winget), Policies, StressTest, SystemInfo, DeepClean, power plans, CompressOS.

## Architecture decisions
- WPF .NET 10 single-file self-contained win-x64 exe, built on Linux (EnableWindowsTargeting).
- Engines (every action = separate child process -> failure isolation; log per action):
  - ultimate: run original .ps1 byte-identical (SHA-256 checked) with `powershell.exe -NoProfile -ExecutionPolicy Bypass -File`, menu answers fed via redirected stdin; free-form prompts validated in UI first. (Needs Windows verification that Read-Host reads redirected stdin.)
  - winutil: harness dot-sources original functions/*.ps1 + config JSON, calls Invoke-WinUtilTweaks apply/undo etc.
  - rytunex: original OptimizeSystemHelper.cs compiled verbatim + verbatim-extracted ExecuteToggleActionAsync/StartInCmd, exe mode `--rytunex <tag> on|off`.
  - winsux: full pipeline runs original winsux.ps1 unchanged (typed confirmation, irreversible).
- App asInvoker; admin actions batched into one elevated runner (`GOATTweaks.exe --runner batch.json`) = one UAC prompt.
- WinSux steptwo sections (1-based line of Write-Host header): REMOVE EDGE 41, REMOVE UWP APPS 126, REMOVE UWP FEATURES 157, REMOVE LEGACY FEATURES 182, REMOVE LEGACY APPS 217, STORE SETTINGS 355, WINDOWS SETTINGS 403, POWER PLAN 935, TIMER RESOLUTION 1152, DISK CLEANUP 1183, RESTORE POINT 1209, RESTARTING 1224. Preamble lines 1-~38 (admin header, Run-Trusted fn, $progresspreference).
- RyTuneX OptimizeSystemHelper.cs: only external deps OptimizationOptions.StartInCmd (1040 calls) + LogHelper.Log/LogError; MemoryHelper defined in same file. StartInCmd at OptimizationOptions.cs:690, RunPowerShell next; ExecuteToggleActionAsync at :996 (switch, 119 cases).
- winutil fns w/o UI deps: Invoke-WinUtilTweaks, Set-WinUtilRegistry/Service/DNS, Invoke-WinUtilFeatureInstall, Install-WinUtilProgramWinget/Choco, Remove-WinUtilAPPX, Invoke-WPFFixesNTPPool/Network/Winget, SystemRepair, UltimatePerformance, Updatesdefault/security, OOSU, Autologin, SSHServer.
